# DM房间分享

房主隧道端集成在Minecraft1.21.1 NeoForge客户端Mod中，使用Kotlin实现。服务器运行独立的Rust[dm-gateway](../../../server/dm-gateway/README.md)，房主无需另外运行隧道程序。

## 开始分享

进入自己的单人世界，在聊天栏输入：

```text
/dm host example.com:25566 alice
```

`example.com:25566`是网关的隧道入口，`alice`是房间名称。房间名称支持中文和空格，UTF-8编码长度最多128字节。例如：

```text
/dm host example.com:25566 小明的生存世界
/dm host [2001:db8::1]:25566 alice
```

IPv6示例地址仅作格式演示，请替换为实际网关地址。

Mod自动开放尚未发布的本地世界，使用新分配的IGS端口，不开启访客作弊权限。如果世界已经通过局域网开放，直接使用现有端口和设置。连接网关的操作在后台进行。

注册成功后，聊天栏会显示可点击复制的加入地址，例如`example.com:26000`。访客在多人游戏中连接这个地址。网关的隧道端口和访客的游戏端口是两个不同入口。

## 查看和停止

```text
/dm status
/dm stop
```

- 一个客户端同一时刻分享一个本地世界。更换网关或房间名称前先执行`/dm stop`。
- 网关断线时自动重试，重试间隔为2秒；已断开的访客需要重新加入。
- 退出当前世界或关闭游戏会自动关闭隧道并停止重试。
- 旧世界或旧分享会话的后台回调不会更新新世界的状态或聊天消息。
- `/dm stop`只停止通过DM网关分享，不停止世界，也不会关闭已经开放的局域网端口；退出世界才会结束该局域网服务。
- 世界开放后，菜单不会像未开放的单人世界一样暂停世界运行。

## 实现范围

客户端通过同一个DMG1协议连接Rust网关，包括房间注册、心跳、访客连接配对和原始TCP字节转发。每名访客使用独立数据连接；网络I/O在后台虚拟线程执行，Minecraft调用和聊天消息回到客户端线程执行。

没有新增身份认证、房间权限或注册表校验。Minecraft本身的握手和游戏协议保持原样。此功能不包含存档同步、备用房主或自动房主迁移。
