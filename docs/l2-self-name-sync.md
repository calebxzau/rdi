# L2玩家自身名称同步

Forge1.20.1、L2Tabs0.3.3且连接双方声明`rdi:l2_names`能力时，自动优化玩家自身的属性修饰符名称同步。没有开关和额外READY消息。其他版本、旧端及其他实体仍使用原L2行为；原L2的`syncPlayerAttributeName`配置仍受尊重。

## 行为

- 客户端的缓存和Mixin在登录前安装。可选能力通道只声明是否支持该行为，不传输名称消息，不修改`rdi:general`或`rdi:batch`。
- 在L2已排队的玩家自身发送入口取消原发送，发生在序列化前；其他实体的追踪发送保持原样。
- 服务器在END阶段LOWEST优先级处理，晚于原L2的NORMAL阶段任务。只在服务器主线程读取玩家当前的可同步属性，包含已经没有修饰符的属性。
- 每个连接仅保存其当前玩家实例、世界、已发送名称和待发送属性。首次初始化、重生或换世界后，在下次END阶段立即发送基线。
- 按属性比较UUID到名称的映射，忽略排列顺序；首个变化开启固定1000ms窗口，后续变化不延后期限。截止时发送各属性的最新完整名称列表；恢复到已发送内容的变化取消发送。
- 使用单调时钟，在tick结束检查；实际延迟是1000ms加下一次tick的调度时间，服务器卡顿时无法保证严格1秒。
- 保留L2 ID1原有字节格式。未包含的属性不变，明确空列表清空该属性缓存。客户端在原版属性包重建修饰符后恢复名称，不修改数值或修饰符实例。
- 客户端在连接、玩家实例、世界变化时清理缓存；服务器在登出、重生、换世界和停止时清理状态。未发送的名称不会阻塞其他Minecraft包。
- 登出时输出候选快照、原L2自身发送抑制次数及实际发送次数。v4和packbatch继续记录真正发送的包，语义去重不记为捕获丢失。
