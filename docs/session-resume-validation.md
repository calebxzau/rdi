# 不退图换节点验证记录

第1阶段，2026-11-02。计划见`docs/session-resume-plan.md`。

## 结论

第1阶段的通过标准全部达到。本机验证覆盖了真实Minecraft客户端和服务端，但线路是本机回环，不代表公网表现。

## 通过标准

| 项目 | 标准 | 1.21.1 NeoForge | 1.20.1 Forge |
|---|---|---|---|
| 被踢次数 | 0 | 0（75次） | 0（75次） |
| 节点静默恢复 | P95≤8秒，最大<15秒 | P95 3.03秒，最大3.03秒 | P95 3.03秒，最大3.04秒 |
| 节点退出恢复 | P95≤3秒 | P95 26ms，最大32ms | P95 16ms，最大16ms |
| 手动切换 | 无明显卡顿，不断线 | P95 22ms | P95 19ms |

每个版本的75次由节点退出30次、节点静默30次、手动切换15次组成，平均分布在站立、跑图和大数据包三种负载下。整段测试玩家始终是同一条连接：1.21.1为22:45:59至22:52:42，1.20.1为23:17:27至23:27:57，中途没有离开或重新进入。

每次故障后都要求服务端回应一条命令，才算恢复成功。

## 其他标准

| 项目 | 结果 |
|---|---|
| 数据一致性 | 64MiB双向传输4组，每组39至52次接管，全部逐字节一致 |
| 正常退出 | 玩家6ms离开房间（1.20.1实测） |
| 强杀游戏客户端 | 玩家0.17秒离开房间（1.20.1实测，本地代理仍在运行） |
| 锚点内存 | 20个会话时RSS峰值10.1MB（Linux），低于基线加30MiB和100MB目标 |
| 旧连接路径 | 现有测试和冒烟测试无回归 |

冒烟测试：20个会话、120秒、经两个节点轮流断开，共480次切换、339MB数据，切换P95 3.10秒，最大3.32秒。

1.20.1在Windows上单人跑图时，锚点工作集峰值15.9MB，命令行版本地代理11.4MB。

## 实际流量

| 负载 | 1.20.1（完整测试） | 1.21.1（单独约27秒测量） |
|---|---|---|
| 站立 | 39KiB/s | 7KiB/s |
| 跑图 | 1190KiB/s，共241MiB | 476KiB/s，共12MiB |
| `/recipe`大数据包 | 72KiB/s | 8KiB/s |

`/recipe`的流量很小，不算真正的大包压力。高流量由合成负载覆盖。

## 第一次1.20.1完整测试的2次失败

第一次完整测试有2次被判定失败，修正测试脚本后重跑，75次全部通过。上表是重跑的结果。

- 第1次：脚本把另一个短连接的结束算成了玩家会话结束。事件记录显示玩家会话没有结束。
- 第2次：跑图时命令回复没有在2秒等待窗口内出现。当时服务端日志有2.2秒的卡顿，时间上吻合，但没有逐条对应证实。脚本改为等待5秒并最多重试4次后，75次都在第一次等待内得到回复。

## 短连接

1.20.1测试时，每分钟出现3条立刻结束的连接，1.21.1测试时没有。代码上很可能是本地master探测房间端口（`HostPresenceService`的`McServerPinger`），没有完全证实。它们不影响玩家连接。

## 构建

## 尚未验证

- 真实公网和真实frp：恢复时间不含网络延迟，frp接受连接和隧道断开时的行为也没有实测。
- 2秒单节点握手时限和3秒失效判定在慢线路上是否会误判。
- 启动器和游戏同时死亡时的真实表现：只有单元测试（锚点20秒回收）。
- 探测次数上限是全部真实游戏测试之后加入的，只经过单元测试和最终的合成负载。
- 不同机器之间的网络环境下的多人同时切换。

## 复现

```sh
# 三个crate各自运行
cargo test
cargo test --release -- --ignored   # common/session-resume-rs：64MiB随机故障

# server/proxy-rs，加上恢复负载
python3 scripts/smoke_load.py --binary target/release/rdi-proxy-rs --connections 20 \
  --seconds 12 --resume-seconds 120 --favicon ../proxy/favicon.png \
  --local-proxy ../../client/local-proxy-rs/target/release/rdi-local-proxy-cli \
  --fault-relay ../../common/session-resume-rs/target/release/examples/fault_relay
```

真实游戏测试用`server/proxy-rs/scripts/resume_game_e2e.py`。先启动开发服务端，再启动脚本和客户端，脚本会点击游戏内的进入按钮。1.21.1要先把开发服务端临时改到其他端口，让出6370给本地代理；1.20.1的加入按钮连接51468，不用改服务端。
