# DM Gateway

DM是Distributed Multiplayer（分布式多人游戏）的缩写。这个独立Rust程序只运行网关服务，通过反向TCP隧道让玩家连接另一台电脑上的Minecraft集成服务器（IGS）。房主端由`client/mc/1.21.1-neoforge`中的Kotlin Mod实现。

一个网关进程承载多个房间。所有房主共用隧道入口，每个房间拥有独立的游戏端口。每名访客使用独立的数据连接，Minecraft数据原样转发。

## 自行构建

在`server/dm-gateway`目录使用支持Rust2024 edition的工具链运行：

```sh
cargo build --release
```

输出为`target/release/dm-gateway`，Windows下为`target/release/dm-gateway.exe`。只需为网关服务器构建此程序，房主电脑使用客户端Mod。首次构建会生成依赖锁文件`Cargo.lock`。此处只提供命令，交付时没有执行构建。

## 运行

以下命令假设网关服务器的可执行文件已经可用。

服务器：

```sh
./dm-gateway --tunnel-listen 0.0.0.0:25566 --game-bind 0.0.0.0 --game-ports 26000-26999
```

这三个参数均可省略，以上是默认值。无参数启动会使用默认配置，也保留`dm-gateway serve ...`写法。服务器网络需允许访问隧道端口和游戏端口范围。

房主使用Minecraft1.21.1客户端Mod进入自己的单人世界，在聊天栏输入：

```text
/dm host example.com:25566 alice
```

两个参数均必填。网关地址支持域名或IP地址；IPv6地址使用`[地址]:端口`格式。房间名称最多128字节UTF-8，可以包含中文和空格。Mod会自动取得IGS端口；世界尚未开放时自动开放局域网，已有局域网设置则直接复用。

注册成功后，聊天栏显示可点击复制的游戏入口，例如`example.com:26000`。访客直接在Minecraft中连接该地址。房主继续在自己的世界里游玩。通过`/dm status`查看连接状态，通过`/dm stop`停止网关分享。

另一个房主可以连接同一个网关：

```text
/dm host example.com:25566 bob
```

网关为bob分配另一个可用游戏端口。不同房主电脑上的IGS可以使用相同的本地端口。完整客户端说明见[DM_GATEWAY.md](../../client/mc/1.21.1-neoforge/DM_GATEWAY.md)。

使用`--help`查看参数。日志默认等级为`info`，可以通过`RUST_LOG`调整：

```powershell
$env:RUST_LOG = "debug"
```

## 房间和连接

- 网关从配置的端口范围按顺序尝试实际绑定，成功后才登记房间。
- 同名房间已有活动房主时，新注册返回占用状态。
- 房主离线后，网关保留该房间的游戏端口；离线期间的新访客连接会被关闭。
- 房主重连同名房间时复用端口，并获得新的UUIDv7会话编号。
- 网关重启后重新分配端口，不保存房间表。
- 数据连接通过会话编号和会话内递增的连接编号配对。这些编号只用于路由，不是身份凭证。
- 某个房主断线只清理它自己的等待连接和转发任务，不会关闭其他房间。
- 房主重连后，访客需要重新加入；已断开的游戏会话不会恢复。

房主主动连接网关，网关不会尝试直接连接房主的公网IP。控制连接负责登记房间、请求新连接和心跳；每名访客的数据通过另一条房主主动建立的TCP连接传输。

## 超时和退出

TCP连接建立及初始隧道握手的超时为5秒，访客等待配对的超时为10秒。网关每15秒发送控制心跳，45秒无响应则结束房主会话；房主也会检测控制连接失联。

客户端Mod断线后每2秒尝试重连。游戏数据传输不设固定空闲超时，使用TCP背压和半关闭语义。控制连接失效时关闭该会话的数据连接；离开当前世界、退出游戏或执行`/dm stop`会停止后台重连。

`/dm stop`只关闭DM隧道，不停止IGS，也不会撤销已经开放的局域网；局域网开放状态持续到退出世界。网关程序按Ctrl+C退出。

## 协议

隧道TCP连接以ASCII字节`DMG1`和1字节角色开始：

| 角色 | 后续字段 |
| --- | --- |
| `1`，房主控制连接 | 房间名长度`u16`，随后为UTF-8房间名 |
| `2`，数据连接 | 会话UUID的16字节，连接编号`u64` |

多字节整数使用大端字节序。控制消息使用1字节操作码：

| 操作码 | 消息 | 后续字段 |
| --- | --- | --- |
| `1` | READY | 会话UUID的16字节，游戏端口`u16` |
| `2` | BUSY | 无 |
| `3` | NO_PORT | 无 |
| `4` | OPEN | 连接编号`u64` |
| `5` | FAILED | 连接编号`u64` |
| `6` | PING | 无 |
| `7` | PONG | 无 |

数据连接头之后立即开始传输原始游戏字节，不额外发送确认帧。隧道头和控制消息不会送入Minecraft连接。

## 首版范围

首版只实现多房间TCP转发，不接入RDI账号、成员权限、注册表校验、世界同步或自动房主迁移。网关不增加认证、TLS或额外压缩；Minecraft自身的握手、压缩和加密数据仍原样通过。

本项目的首次实现按要求不运行构建、测试或游戏验证，不代表已验证兼容所有Minecraft版本或整合包。

原Rust房主端已移入[DEL归档](../../DEL/dm-gateway-rust-host-moved-to-client-20260916/server/dm-gateway/src/host.rs)，当前程序不再提供`host`子命令。
