# DM Gateway

DM是Distributed Multiplayer（分布式多人游戏）的缩写。这个独立Rust程序只运行网关服务，通过反向TCP隧道让玩家连接另一台电脑上的Minecraft集成服务器（IGS）。房主端由`client/mc/1.21.1-neoforge`中的Kotlin Mod实现。

一个网关进程承载多个房间。所有房主共用隧道入口，每个房间拥有独立的游戏端口。每名访客使用独立的数据连接，Minecraft数据原样转发。

## 自行构建

在`server/dm-gateway`目录使用支持Rust2024 edition的工具链运行：

```sh
cargo build --release
```

输出为`target/release/dm-gateway`，Windows下为`target/release/dm-gateway.exe`。只需为网关服务器构建此程序，房主电脑使用客户端Mod。首次构建会生成依赖锁文件`Cargo.lock`。此处只提供命令，交付时没有执行构建。

## 运行

以下命令假设网关服务器的可执行文件已经可用。

服务器：

```sh
./dm-gateway --master http://127.0.0.1:8080 --tunnel-listen 0.0.0.0:25566 --game-bind 0.0.0.0 --game-ports 26000-26999
```

这些参数均可省略，以上是默认值。无参数启动会使用默认配置，也保留`dm-gateway serve ...`写法。服务器网络需允许访问隧道端口和游戏端口范围。

房主使用Minecraft1.21.1客户端Mod进入自己的单人世界。客户端通过`-Drdi.dm.server`配置的dm-master上传初始化资料并取得UUIDv7房间ID，然后连接本网关。网关通过`--master`检查房间存在；控制隧道注册时只发送hostId的16字节UUID。

注册成功后，聊天栏显示可点击复制的游戏入口，例如`example.com:26000`。访客通过多人游戏界面的DM入口输入永久房间ID加入。房主继续在自己的世界里游玩，通过`/dm status`查看连接状态；退出世界会停止托管。

不同房间各自占用一个活动游戏端口。完整客户端说明见[DM_GATEWAY.md](../../client/mc/1.21.1-neoforge/DM_GATEWAY.md)。

使用`--help`查看参数。日志默认等级为`info`，可以通过`RUST_LOG`调整：

```powershell
$env:RUST_LOG = "debug"
```

## 房间和连接

- 网关从配置的端口范围按顺序尝试实际绑定，成功后才登记活动host。
- 同一host已有活动房主时，新注册返回占用状态；未知host或master不可用时注册失败。
- 房主离线后，网关关闭该host的游戏监听器、等待连接和转发任务，并释放游戏端口。
- 房主重连时获得新的UUIDv7会话编号和可能不同的游戏端口。
- 永久房间和初始化资料由dm-master保存，网关只保存内存中的活动会话。
- 网关通过HTTP向master报告host上线、离线和每10秒心跳；master要求同步时发送当前活动会话完整列表。
- 数据连接通过会话编号和会话内递增的连接编号配对。这些编号只用于路由，不是身份凭证。
- 某个房主断线只清理它自己的等待连接和转发任务，不会关闭其他房间。
- 房主重连后，访客需要重新加入；已断开的游戏会话不会恢复。

房主主动连接网关，网关不会尝试直接连接房主的公网IP。控制连接负责登记房间、请求新连接和心跳；每名访客的数据通过另一条房主主动建立的TCP连接传输。

## 超时和退出

TCP连接建立及初始隧道握手的超时为5秒，访客等待配对的超时为10秒。网关每15秒发送隧道控制心跳，45秒无响应则结束房主会话；房主也会检测控制连接失联。网关到master的状态心跳每10秒发送一次，失败不会中断已有游戏转发。

客户端Mod断线后每2秒尝试重连。游戏数据传输不设固定空闲超时，使用TCP背压和半关闭语义。控制连接失效时关闭该会话的数据连接；离开当前世界或退出游戏会停止后台重连。

网关程序按Ctrl+C退出。

## 协议

隧道TCP连接以ASCII字节`DMG1`和1字节角色开始：

| 角色 | 后续字段 |
| --- | --- |
| `1`，房主控制连接 | hostId的16字节UUID |
| `2`，数据连接 | 会话UUID的16字节，连接编号`u64` |

多字节整数使用大端字节序。控制消息使用1字节操作码：

| 操作码 | 消息 | 后续字段 |
| --- | --- | --- |
| `1` | READY | 会话UUID的16字节，游戏端口`u16` |
| `2` | BUSY | 无 |
| `3` | NO_PORT | 无 |
| `8` | HOST_NOT_FOUND | 无 |
| `9` | MASTER_UNAVAILABLE | 无 |
| `4` | OPEN | 连接编号`u64` |
| `5` | FAILED | 连接编号`u64` |
| `6` | PING | 无 |
| `7` | PONG | 无 |

数据连接头之后立即开始传输原始游戏字节，不额外发送确认帧。隧道头和控制消息不会送入Minecraft连接。

## 首版范围

首版只实现多房间TCP转发，不接入RDI账号、成员权限、注册表校验、世界同步或自动房主迁移。网关不增加认证、TLS或额外压缩；Minecraft自身的握手、压缩和加密数据仍原样通过。

网关构建和测试需要在`server/dm-gateway`目录运行`cargo fmt --check`、`cargo check`和`cargo test`。真实双机联机仍需单独验证。

原Rust房主端已移入[DEL归档](../../DEL/dm-gateway-rust-host-moved-to-client-20260916/server/dm-gateway/src/host.rs)，当前程序不再提供`host`子命令。
